Website-Bauplan SG Technik

Wo jede Datei liegt und wie aus ihr die fertige Website sg-technik.at wird. Zuerst der Weg vom Quellcode in den Browser und die Bausteine, aus denen die Website besteht. Danach der Verbindungsplan aller Dateien unter src/ und public/: Ein Klick auf eine Datei erklärt genau, was sie tut. Am Ende der ganze Projektordner.

Vom Quellcode zur fertigen Seite

Die Website ist eine statische Astro-Seite. Beim Bauen entstehen fertige HTML-Dateien. Ein Server, der zur Laufzeit Seiten zusammensetzt, wird nicht gebraucht.

1 · QUELLEN

Projektordner

src/ enthält Seiten, Komponenten, Inhalte, Skripte, Stile und Bilder. public/ enthält Dateien, die unverändert ausgeliefert werden: Schriften, Logos und _headers.

2 · BAUEN

npm run build

Astro 7 setzt jede Seite aus Layout und Komponenten zu HTML zusammen. Vite bündelt die Skripte, Tailwind 4 erzeugt das CSS. Fotos werden in mehrere WebP-Größen umgerechnet. Einstellung: astro.config.mjs.

3 · ERGEBNIS

dist/

Pro Seite ein Ordner mit index.html. In dist/_astro/ liegen die gebündelten JS- und CSS-Dateien sowie rund 300 optimierte Bilder. Dazu kommen fonts/, logo/ und _headers.

4 · HOSTING

Netlify

Netlify liefert dist/ über sein Netz aus und setzt die Sicherheitsheader aus _headers. Sein Formulardienst nimmt das Kontaktformular an, prüft es auf Spam und leitet es per E-Mail weiter.

5 · BROWSER

Fertige Website

Das HTML ist sofort lesbar. Kleine Skripte bauen danach das animierte Logo, die Winterdienst-Straße, die Serpentine, die Galerie und die Anlagensimulation auf. Cookies und lokalen Speicher nutzt die Seite nicht.

Beim Entwickeln wird nichts gebaut: npm run dev startet einen Server auf localhost:4321, der jede Änderung sofort anzeigt. npm run dev:handy macht ihn im WLAN unter macbook-air-von-simon.local:4321 erreichbar.

So ist die Website aufgebaut

Die Website funktioniert wie ein Baukasten. Jede Seite wird aus fertigen Bausteinen zusammengesetzt. Texte und Zahlen stehen getrennt davon in eigenen Dateien. Um zu verstehen, was eine Datei tut, muss man vor allem wissen, wann ihr Code läuft.

beim Bauen auf dem Mac oder bei Netlify

Bei npm run build führt Astro den Vorbereitungsteil jeder .astro-Datei aus, holt Texte aus src/content/ und schreibt daraus fertiges HTML. Danach gibt es diesen Code nicht mehr. Der Besucher bekommt nur das Ergebnis, eine gewöhnliche HTML-Datei.

im Browser beim Besucher

Nur der Code in <script>-Blöcken und in src/scripts/ wird mitgeschickt und läuft beim Besucher. Er sorgt für Bewegung und Bedienung: Menü, Zahlen-Zählen, Animationen, Galerie, Simulation. Ohne JavaScript ist jede Seite trotzdem vollständig lesbar.

  • Seiten

    src/pages/*.astrobeim Bauen

    Jede Datei ist eine Adresse der Website, und der Dateiname bestimmt die URL: referenzen.astro wird zu sg-technik.at/referenzen, index.astro zur Startseite.

    Eine Seite enthält kaum eigenen Inhalt. Sie legt fest, welche Bausteine in welcher Reihenfolge erscheinen, und gibt Titel und Beschreibung für Suchmaschinen an das Layout weiter. Ausnahmen sind Impressum, Datenschutz und Cookie-Richtlinie, deren Text direkt in der Seite steht.

    Beispiel: leistungen.astro besteht nur aus BaseLayout, ProcessSection, CtaBand und WinterRoad.

    Hier änderst du: Reihenfolge der Abschnitte, Seitentitel. Eine neue Seite ist eine neue Datei hier plus ein Eintrag in navigation.ts.

  • Layout

    src/layouts/BaseLayout.astrobeim Bauen

    Der gemeinsame Rahmen, in den jede Seite gesteckt wird. Er enthält alles, was auf jeder Seite gleich ist: den unsichtbaren <head> mit Titel, Beschreibung und Favicon, oben den Header, unten den Footer und die globalen Stile.

    Die Stelle <slot /> im Layout markiert, wo der Inhalt der jeweiligen Seite eingesetzt wird.

    Hier änderst du: alles, was auf allen Seiten gleichzeitig erscheinen oder anders sein soll.

  • Komponenten

    src/components/*.astrobeim Bauen im Browser

    Wiederverwendbare Bausteine, jeweils ein Abschnitt oder ein Element der Seite. Eine Komponente kann auf mehreren Seiten stehen (CtaBand steht auf vier) und selbst andere Komponenten enthalten (Hero enthält LogoMark). Sie bekommt ihre Texte aus src/content/.

    Jede .astro-Datei hat bis zu vier Teile:

    ---
import { hero } from '../content/site';   ← Vorbereitung, läuft beim Bauen
---
<section class="bg-paper py-20">          ← HTML mit Tailwind-Klassen
  <h1>{hero.headline}</h1>                ← {…} setzt Daten ein
</section>
<style> … </style>                       ← gilt nur für diese Komponente
<script> … </script>                     ← läuft im Browser

    Hier änderst du: Aussehen und Aufbau eines Abschnitts, also Anordnung, Abstände, Farben und das Verhalten beim Klicken.

  • Browser-Skripte

    src/scripts/im Browser

    TypeScript-Code für alles, was sich bewegt oder auf Eingaben reagiert und für einen <script>-Block in einer Komponente zu groß ist: das animierte Logo, die Winterdienst-Straße, die Serpentine auf der Danke-Seite und die Anlagensimulation.

    Vite bündelt die Skripte beim Bauen zu kleinen JavaScript-Dateien in dist/_astro/. Die Komponente entscheidet, wann ein Skript geladen wird. Die Straße wird zum Beispiel erst nachgeladen, wenn das Fenster breit genug ist. Alle Animationen bleiben still, wenn im Betriebssystem „Bewegung reduzieren“ eingeschaltet ist.

    Hier änderst du: wie eine Animation oder die Simulation funktioniert. Für Mengen, Tempo und Größen reichen meist die Stellwerte in src/content/.

  • Inhalte & Stellwerte

    src/content/*.tsbeim Bauen teils im Browser

    Daten statt Darstellung. Inhalte sind Texte, Firmendaten, Menüpunkte, Referenzprojekte und Rechtsangaben. Stellwerte sind Zahlen, mit denen sich eine Animation oder die Simulation einstellen lässt, ohne den Code zu verstehen, ähnlich wie Sollwerte an einer Anlage.

    Die Komponenten lesen diese Dateien. Wer einen Text oder Wert ändert, muss das HTML also nicht anfassen. Braucht ein Browser-Skript die Werte, etwa die Straße oder die Simulation, kommen sie beim Bauen mit ins JavaScript.

    Beispiele: site.ts enthält die Kennzahlen im Hero („15.000 l/h“). winterdienst.ts regelt Schneemenge, Salzmenge und Fahrzeuggröße. anlagensimulation.ts enthält Siloinhalt, Löseleistung und Zeitraffer.

    Hier änderst du: Texte, Zahlen, Projekte, Rechtsangaben und Stellwerte.

  • Stile, Bilder, Schriften

    src/styles/ · src/assets/ · public/beim Bauen

    global.css lädt Tailwind und legt die Farben (Navy, Kupfer, Papierweiß) und Schriften fest. Die meisten Stile stehen als Tailwind-Klassen direkt im HTML der Komponenten, zum Beispiel text-navy-800 für die Schriftfarbe oder py-20 für den Abstand oben und unten.

    Bilder in src/assets/ optimiert Astro beim Bauen. Es rechnet sie in WebP und mehrere Größen um, damit ein Handy kein Desktop-Foto laden muss. Dateien in public/ werden unverändert kopiert und sind unter ihrem Pfad erreichbar, etwa /fonts/… oder /logo/….

    Hier änderst du: Farben und Schriften für die ganze Website (global.css), Fotos (src/assets/) und Logos (public/logo/). Die Regeln des Designs stehen in DESIGN.md.

Beispiel: Jemand öffnet sg-technik.at/leistungen

  1. Netlify schickt die fertige Datei dist/leistungen/index.html. Darin stehen Header, die sieben Schritte, das Kontaktband und der Footer schon vollständig als HTML. Astro hat sie beim Bauen aus leistungen.astro, BaseLayout, ProcessSection, CtaBand und den Texten in site.ts zusammengesetzt.
  2. Der Browser lädt die CSS-Datei aus /_astro/ und die Schriften aus /fonts/. Die Seite ist jetzt fertig lesbar.
  3. Das Skript im Header verbindet das Handy-Menü mit seinem Knopf und schaltet die Schalter für die Zierde frei, etwa den für die Straße. Dass „Leistungen“ im Menü als aktuelle Seite markiert ist, hat Astro schon beim Bauen ins HTML geschrieben.
  4. Das Skript von WinterRoad prüft, ob das Fenster mindestens 85 rem breit ist und „Bewegung reduzieren“ aus ist. Nur dann lädt es winter-road, route-leistungen und die Stellwerte aus winterdienst nach.
  5. route-leistungen.ts misst die Lage der Schritte und legt den Straßenverlauf fest. scene.ts rechnet daraus einmal die verschneite und die geräumte Straße vor.
  6. Beim Scrollen fährt das Räumfahrzeug mit. winter-road.ts malt nur noch den gerade geräumten Streifen nach und streut Salz.

Verbindungsplan

Jede Linie bedeutet: Die linke Datei nutzt die rechte. Klick auf eine Datei erklärt rechts genau, was in ihr passiert, wann ihr Code läuft und was man dort ändert. Im Plan leuchtet auf, was sie braucht (kupfer) und wer sie braucht (blau). Für eine Seite siehst du rechts zusätzlich, aus welchen Bausteinen sie besteht.

Seite
wird von der Auswahl genutzt nutzt die Auswahl alle übrigen Verbindungen

Auf schmalen Bildschirmen lässt sich der Plan seitlich verschieben.

Der ganze Projektordner

Nur ein Teil des Ordners landet auf der Website. Der Rest ist Arbeitsmaterial, Dokumentation oder bleibt bewusst außerhalb von Git.

Websitewird gebaut und ausgeliefert erzeugtentsteht automatisch ArbeitDoku, Prüfung, Werkzeuge lokalper .gitignore nicht in Git
  • src/WebsiteAlles, woraus Astro die Seiten baut.
  • pages/9 Seiten. Der Dateiname ist die Adresse: leistungen.astro → /leistungen.
  • layouts/BaseLayout.astro, der gemeinsame Rahmen jeder Seite.
  • components/16 Bausteine wie Header, Hero, Kontakt, Galerie oder die Animationen.
  • content/13 TypeScript-Dateien mit Texten, Firmendaten und Stellwerten. Inhalte ändert man hier, nicht im Markup.
  • scripts/Code, der im Browser läuft: Logo, Serpentine, winterdienst/ (9 Dateien) und anlagensimulation/ (9 Dateien).
  • styles/global.css (Tailwind, Schriften, Farben) und anlagensimulation.css.
  • assets/Fotos und Texturen, die Astro beim Bauen optimiert: referenzen/ (7 Projekte, 32 JPG), wald/, winterdienst/, Serpentinen-Luftbild.
  • public/WebsiteWird 1:1 nach dist/ kopiert: fonts/ (6 WOFF2, IBM Plex und Montserrat fürs Logo), logo/ (3 SVG), _headers.
  • astro.config.mjsWebsiteDomain sg-technik.at, Tailwind-Plugin, erlaubter Handy-Hostname.
  • package.jsonWebsiteAbhängigkeiten (Astro, Tailwind, TypeScript) und Befehle (dev, build, preview). Dazu package-lock.json, tsconfig.json, .nvmrc (Node 24).
  • dist/erzeugtlokalDie fertige Website nach npm run build. Das wird ausgeliefert.
  • node_modules/ · .astro/erzeugtlokalInstallierte Pakete und Zwischenspeicher von Astro.
  • docs/ArbeitTechnische Doku.
  • animationen/Herkunft der Prototypen, Winterdienst-Straße, Anlagensimulation.
  • datenschutz/Arbeitsplan, Consent-Konzept, Checkliste, Wiedervorlage-PDF.
  • scripts/ArbeitWerkzeuge außerhalb der Website: sim-pruefung/ (Browserprüfungen), Texturen-Generator, Wiedervorlage-PDF.
